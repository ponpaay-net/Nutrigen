[KRITIS-04] IDOR: Portal Ibu membuka data balita mana pun hanya dengan
            mengubah angka ID di URL
----------------------------------------------------------------
Status    : SELESAI 26 Ags 2026 dan sudah diuji dengan PortalIbuAccessTest
Lokasi    : app/Http/Controllers/PortalIbu/PortalIbuController.php
            baris 24-33 (fungsi getActiveBalita)
Masalah   : getActiveBalita() hanya melakukan:
              Balita::with(...)->find(request('balita'))
            Tidak ada pengecekan apakah pemilik signed URL berhak atas
            balita tersebut.
Skenario serangan:
            Ibu A menerima signed URL untuk balita miliknya:
            /portal-ibu/dashboard?balita=5&signature=...
            Ubah jadi ?balita=7 (tetap dengan signature yang sama) ->
            data balita 7 (milik orang lain) tampil lengkap: nama anak,
            riwayat pengukuran, grafik, jadwal posyandu.
            Ini melanggar privasi kesehatan anak (data medis).
Dampak    : Data kesehatan balita bocor antar keluarga. Fatal untuk
            kredibilitas aplikasi kesehatan di mata juri/user.
Tindakan  (pilih salah satu strategi, JANGAN dicampur):
  Opsi A (DIPILIH - SELESAI 26 Ags 2026):
    [✓] Di approve() PuskesController: signed URL kini membawa balita + orang_tua
        (lihat PuskesmasController::approve(), TTL via config('portal.link_ttl_days'))
    [✓] Di getActiveBalita(): scoped where('orang_tua_id', request('orang_tua'))
        -> kombinasi balita+ortu yang tidak cocok = null = empty state
    [✓] SEMUA link internal portal meneruskan orang_tua + temporarySignedRoute
        (home x8, growth back-button, bottom-navigation x3, child-selector)
  Opsi B (tidak dijalankan): token akses per orang_tua
  [✓] Buat test: tests/Feature/PortalIbuAccessTest.php (7 tes / 16 asersi, PASS)
      - data anak sendiri tampil; anak orang lain kosong walau signature valid
      - tamper balita_id -> 403; tanpa orang_tua -> kosong; expired -> 403
      - child-selector hanya anak kandung; pengukuran pending tidak bocor
